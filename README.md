# 德州扑克相对牌力概率训练器

一个纯前端训练器：看到自己的 2 张底牌 + 公共牌后，快速判断

- 哪些牌型能压过我
- 各牌型的大致概率
- 同牌型中比我大的概率
- 具体是什么起手牌（A8 / A3 / 83 …）
- 各有多少组合

公共牌可以一路发到河牌，**翻牌圈 / 转牌圈 / 河牌圈都能出题与作答**：

| 街道 | 公共牌 | 对手组合数 |
| --- | --- | --- |
| 翻牌圈 | 3 张 | `C(47,2) = 1081` |
| 转牌圈 | 4 张 | `C(46,2) = 1035` |
| 河牌圈 | 5 张 | `C(45,2) = 990` |

> 本版默认对手从剩余未知牌中**完全随机**获得 2 张牌，每个组合等权。
> 所有概率都由当前街道的组合精确枚举得出，**没有任何硬编码**。

项目位于 `poker-trainer/` 子目录，与仓库里原有的菜谱应用完全独立。

## 2. 核心数据结构

```ts
type Rank = '2'|'3'|'4'|'5'|'6'|'7'|'8'|'9'|'T'|'J'|'Q'|'K'|'A';
type Suit = 's' | 'h' | 'd' | 'c';

interface Card { rank: Rank; suit: Suit; }

type Street = 'flop' | 'turn' | 'river';

interface Scenario {
  hero: [Card, Card];
  flop: [Card, Card, Card];
  turn?: Card;   // 发了转牌就是转牌圈
  river?: Card;  // 发了河牌就是河牌圈
}

enum HandCategory {
  HighCard = 0, OnePair = 1, TwoPair = 2, Trips = 3,
  Straight = 4, Flush = 5, FullHouse = 6, Quads = 7, StraightFlush = 8,
}

interface HandValue {
  category: HandCategory;
  tiebreak: number[]; // 从重要到次要
}
```

牌面工具（`src/poker/cards.ts`）：`boardCards(s)`、`knownCards(s)`、`streetOf(s)`、`remainingBoardCards(s)`、`getRemainingDeck(s)`（各街分别为 47 / 46 / 45 张）。

`HandValue` 示例：

| 牌面 | category | tiebreak |
| --- | --- | --- |
| `A♠ A♥ K♦ 8♣ 3♦` | `OnePair` | `[14, 13, 8, 3]`（A 对，K/8/3 踢脚） |
| `A♠ A♥ K♦ K♣ Q♦` | `TwoPair` | `[14, 13, 12]` |
| `A♥ 2♠ 3♦ 4♣ 5♥` | `Straight` | `[5]`（5 高顺，A 当 1） |

分析结果：

```ts
interface ScenarioAnalysis {
  scenario: Scenario;
  street: Street;                     // 当前街道
  remainingBoardCards: number;        // 还要发几张公共牌（2 / 1 / 0）
  remainingCount: number;             // 未知名张数（47 / 46 / 45）
  heroHandValue: HandValue;           // Hero 用已知 5~7 张取最优
  totalOpponentCombos: number;        // 1081 / 1035 / 990
  aheadCount: number; tieCount: number; behindCount: number;
  aheadProbability: number; tieProbability: number; behindProbability: number;
  byCategory: CategoryAnalysis[];     // 9 个牌型
  sameCategory: SameCategoryAnalysis;
  results: OpponentHandResult[];      // 全部明细（调试用）
}
```

## 3. 核心算法

`analyzeScenario(scenario)` 完全按需求伪代码实现，对所有街道一致：

```text
52 张牌
  -> 移除全部已知牌（Hero 2 + 公共牌 3/4/5）= 47 / 46 / 45 张
  -> 枚举 C(n,2) = 1081 / 1035 / 990 个对手组合
  -> 对每个组合 evaluateBestHand([对手2张 + 公共牌])
  -> compareHandValues(对手, Hero)
  -> 聚合成 ahead / tie / behind（分母 = 当前街道的组合数）
  -> 按 9 个牌型聚合，再按类型聚合：常规牌型用底牌点数（A8 / 83），一对用成对点数并区分「配对公共牌 / 口袋对」，同花用高张
  -> 同一牌型内概率完全相同的类型再合并成一行，行名列出全部成员（如「配对公共牌 K / 9 / 6」「8 / 7高同花」）
  -> 同牌型单独聚合，使用条件概率分母 totalCount
```

关键点：

- **5~7 张取最优五张**：`evaluateBestHand(cards)` 枚举 `C(6,5)=6` / `C(7,5)=21` 个子集取最大，所以转牌 / 河牌圈“哪些牌能压过我”依然精确。
- **A2345 = 5 高顺子**（A 当 1），已覆盖普通顺子与同花顺。
- **同牌型也可能压过 Hero**：训练器判定“能否压过”依据 `category.aheadCount > 0`，而不是 `category > hero.category`。
- 两种概率严格区分：
  - 占全部随机手牌：`aheadCount / 当前街道组合数`
  - 同牌型条件下领先：`sameCategory.aheadCount / sameCategory.totalCount`
- 概率区间为 `[min, max)`，最后一个区间包含 100%，没有重叠。

### 街道推进（发转牌 / 发河牌）

`dealNextStreet(scenario, rng = Math.random)` 负责把牌面往前推一条街：

```text
翻牌圈 --发转牌--> 转牌圈 --发河牌--> 河牌圈 --再发--> 原样返回
```

- 新牌从 `getRemainingDeck(scenario)`（即全部未知牌）中**等概率抽一张**，不偷看任何人的底牌。
- 已发的公共牌不会被覆盖，河牌圈之后再调用会原样返回（幂等）。
- 每发一条街，`analyzeScenario` 的分母、`analyzeDraws` 的“下一张 / 发完为止”语义都会自动跟着变，**不需要任何特例分支**。

### Fixture 输出（手工核对）

`scripts/inspect.ts` 对 `A♠K♦ / A♥8♣3♦` 的实际输出：

```text
翻牌圈（还要发 2 张公共牌）
Hero: 一对A，K83踢脚
总体: 领先 28 / 平手 6 / 落后 1047 = 1081
概率: 2.59% / 0.56% / 96.85%

能压过 Hero 的牌型:
  两对: 21 组合 (1.94%)
    83: 9 组合 (0.83%)
    A8 / A3: 12 组合 (1.11%)
  三条: 7 组合 (0.65%)
    88 / 33: 6 组合 (0.56%)
    AA: 1 组合 (0.09%)

同牌型:
  一对 总数 369
  比你大 0 (0.00%) / 平手 6 / 比你小 363
```

同一手牌把转牌与河牌发出来（`--board="Ah 8c 3d 2s 9h"`），结果会自动换成河牌圈的分母：

```text
河牌圈（还要发 0 张公共牌）
Hero: 一对A，K98踢脚
总体: 领先 107 / 平手 6 / 落后 877 = 990
```

- 两对合计 `21 = A8(6) + A3(6) + 83(9)`，与需求第 54~57 条完全一致（A8 / A3 概率相同，展示时合并为一行）。
- Blocker 由算法动态计算：剩余 A=2、8=3、3=3，故 A8=2×3=6、A3=2×3=6、83=3×3=9。

### 后续听牌分析（`src/poker/draws.ts`）

回答“我这手听牌到底能补成多少”与“对手拿到听牌并补成的概率有多大”。同样是**精确枚举**，不用蒙特卡洛。

```text
已知 5~7 张牌（Hero 2 + 已发公共牌）
  -> 先判断“现在还没有成型”的听牌目标（顺子 / 同花）
  -> 下一张牌：池子里每张牌逐个试，数出真正能补成的张数 = outs
  -> 发完为止：枚举 C(n,2) 个后续组合，数出能补成的组合数
  -> 还要发两张、但下一张 0 张补牌而两张能补成 => 后门听牌
```

| 街道 | 下一张（next） | 发完为止（final） | 后门听牌 |
| --- | --- | --- | --- |
| 翻牌圈（还要发 2 张） | 转牌 `47` 张（Hero）/ `45` 张（对手） | 转牌 + 河牌 `C(47,2)=1081` / `C(45,2)=990` | 成立 |
| 转牌圈（还要发 1 张） | 河牌 `46` 张 / `44` 张 | **与「下一张」同一批牌**（`46` / `44`） | 不成立（只剩一张牌，不可能“连来两张”） |
| 河牌圈（不用再发） | — | — | 面板不显示：已经没有后续牌可发 |

代码里的字段叫 `next*` / `final*`（而不是 `turn*` / `river*`），就是为了同一套逻辑能直接跑在任意街道上：`remainingBoardCards === 1` 时 `next` 与 `final` 数值相同，界面上也只显示一列。

关键点：

- **判断“补成”用的是花色张数 / 点数位掩码，不是牌型比较**：葫芦、四条并不包含同花，所以不能用“牌型 ≥ 同花”来判断；顺子同理（预计算 8192 项 `STRAIGHT_MASK_TABLE`，含 A2345 轮子）。
- **只把“现在还没成型”的目标当听牌**：同花听牌要求当前同花色恰好 4 张，顺子听牌要求再加 1 张就能连成 5 张。已成型的牌型不会被当成听牌（注意：这是用**全部已知牌**判定的，所以转牌 / 河牌发到同花后就不会再算同花听牌）。
- **顺子听牌按补牌点数分类**：1 个点数 = 卡顺（4 张）、2 个点数 = 两头顺（8 张）、≥3 个点数 = 多卡口。
- **对手侧每类听牌的组合数是重叠的**（同一个组合可能既是同花听牌又是顺子听牌），所以额外给出一条不重叠的三分法：`有立即听牌 + 只有后门听牌 + 完全没有听牌 = 当前街道组合数`。

经典数字（全部由枚举得出，测试里逐一锁定）：

| 听牌 | 补牌 | 下一张补成 | 到河牌补成 |
| --- | --- | --- | --- |
| 同花听牌（4 张同花） | 9 | `9/47 = 19.15%` | `378/1081 = 34.97%` |
| 两头顺（8 张补牌） | 8 | `8/47 = 17.02%` | `340/1081 = 31.45%` |
| 卡顺（4 张补牌） | 4 | `4/47 = 8.51%` | `178/1081 = 16.47%` |
| 后门同花（3 张同花） | 0 | `0%` | `C(10,2)=45/1081 = 4.16%` |
| 同花听牌（转牌圈，只剩一张） | 9 | `9/46 = 19.57%`（= 最终补成） | —— |

## 4. 训练页面流程

1. **显示牌面**：Hero 两张 + 翻牌（还没发的公共牌显示为虚线空位），并显示 Hero 当前牌型与当前街道（不泄露概率）。
2. **选择压制牌型**：8 个成牌型多选（一对及以上，不含「高牌」）；同牌型更大的组合也算正确。
3. **确认牌型**后，对每个已选牌型选择「该牌型且压过你」的概率区间（分母 = 当前街道组合数）。
4. **同牌型判断**：在“对手与 Hero 同牌型”的条件下，选择「比你大」的概率区间（分母为同牌型总数）。仅当 Hero 是成牌时才出现；Hero 是高牌时本题跳过（题量变为 2 步，直接提交）。
5. **提交并揭晓**：结果页分成选项卡查看（见下）。
6. **发下一条街**：结果页底部有「**发转牌**」/「**发河牌**」按钮，发牌后公共牌变化，**当成新的一题重新作答**；河牌发完后按钮变成「下一题」，换一手全新牌。
7. 顶部统计：牌型判断正确率、概率区间正确率、同牌型判断正确率、连续正确次数。

> 每一街都是独立的一题（相同的三步流程），所以转牌 / 河牌圈也能练“对手现在能压过我多少”。
> 统计口径不区分街道，所有街道的正确率合在一起。

### 结果页选项卡

结果页不再把几块内容纵向堆在一起，而是选项卡，一次只看一块：

| 选项卡 | 内容 | 卡片上的摘要 / 标记 |
| --- | --- | --- |
| 总体牌力 | 领先 / 平手 / 落后占比条 + 领先牌型构成 | 对手领先概率 |
| 能压过你的牌型 | 每种能压过你的牌型（含逐个点数类型、具体花色）+ 你的估计与对错 | `n 种 · 组合数 / 当前街道组合数`，以及牌型判断 ✓ / ✗ |
| 同牌型内部（`牌型`） | 同牌型中比你大 / 平 / 小的条件概率 + 具体手牌 | `同牌型总数 · 比你大 x%`，以及同牌型判断 ✓ / ✗ |
| 后续听牌（转牌 / 河牌） | 你的听牌与对手的听牌（顺子 / 同花） | 翻牌圈：`顺子 / 同花能补成多少`；转牌圈：`后续听牌（河牌）` |

- 翻牌圈 4 个选项卡；转牌圈仍 4 个（听牌列改叫「河牌」）；**河牌圈只有 3 个**——公共牌已发完，听牌选项卡自动隐藏。

实现要点：

- **本题小结**：作答后选项卡上方先给一行「牌型判断 / 概率区间 x / y 对 / 同牌型判断」的对错，一眼就能看出哪里错了，不用逐个选项卡找。
- **懒渲染**：只渲染当前选项卡的那一块。顺子的听牌枚举只在你切到「后续听牌」时才跑，答题时不计算。
- 选项卡上的 ✓ / ✗ 对应「这一步答对没有」：能压过你的牌型 → 牌型多选是否正确；同牌型内部 → 同牌型区间是否正确（Hero 是高牌时不要求作答，因此不打标记）。概率区间的对错在面板内逐条标出。
- 直接看答案模式下没有作答，因此不打 ✓ / ✗。
- 窄屏（≤ 520px）自动改用短标题并隐藏摘要行，选项卡仍在一行内（高约 50px）。
- 选项卡样式为 `position: sticky`（吸顶），方便在不滚回顶部的情况下切换。
- 语义上用「一组开关」（`role="group"` + `aria-pressed`）而不是 `tablist`，因为面板是切一个才挂载一个的，这样不依赖方向键导航也不会让屏幕阅读器以为存在隐藏面板。

### 后续听牌面板

结果页「后续听牌（转牌 / 河牌）」选项卡里分两块：

- **你的听牌**：每个听牌一行，列出补牌点数与具体补牌（如 `2♠ 6♠ …`），以及「转牌 `n/47`」「到河牌 `n/1081`」两种成牌概率；后门听牌会打上「后门 · 转牌补不成，需连来两张」标签；多于一种听牌时再给一行「至少补成一种听牌」的并集。**转牌圈只剩一张河牌，所以只显示「河牌 `n/46`」一列**。
- **对手的听牌**：先给不重叠的三分法（有立即听牌 / 只有后门听牌 / 完全没有听牌），再按听牌类型列组合数与占比，以及「下一张补成（平均）」「到河牌补成（平均）」「拿到且补成」三个指标；最后一行为标题数字——「随机对手拿到听牌并在河牌前补成」的概率（括号内是只看“有听牌”时的条件概率）。转牌圈会把「到河牌补成」这一列并掉，表格只剩 4 列。

颜色约定：**红色 = 该类听牌占全部随机组合；蓝色 = 拿到该类听牌后的平均补成率；紫色 = 对手拿到该类听牌且真的补成**。

这一面板只在结果页渲染，而且只有切到该选项卡才计算（由 `ResultBreakdown` 挂载），因此**答题时完全不会触发枚举，不会拖慢答题**。同花听牌行会带花色（如「同花听牌 ♠」）。河牌圈没有听牌选项卡，`analyzeDraws` 也会直接短路返回空结果。

### 直接看答案开关

右上角有「**直接看答案**」开关（选择会记入 localStorage）：

- **打开时**：跳过第 2~4 步，直接按未作答方式渲染结果页（隐藏所有「你的估计 / ✓ 正确 / ✗ 错误」等内容），也**不计入任何统计**。
- 打开状态下点「下一题」仍是直接看答案，只是换一组牌；点「**发转牌 / 发河牌**」也会继续看新一条街的答案。
- **关掉时**：回到当前这题的选择流程，之前已填的答案仍在，可继续作答。

答案在提交前完全不显示；结果页每次展开的花色组合都来自实际枚举。

## 5. 测试运行方式

```bash
cd poker-trainer
npm install
npm test            # 等价于 vitest run
npm run test:watch  # 监听模式
```

覆盖点：

- 52 张唯一牌、剩余 47 / 46 / 45 张、场景去重校验（转牌 / 河牌与已知牌重复会报错）
- `streetOf` / `boardCards` / `knownCards` / `remainingBoardCards` 与街道一致
- `evaluateBestHand`：6 / 7 张取最优五张，随机 60 轮与暴力 `C(n,5)` 结果完全一致
- 9 种牌型识别、级别顺序、全部 Tie Break
- 作答只覆盖 8 种成牌（一对及以上）；`高牌` 不要求选择与猜概率，也不参与评分（结果页仍展示其精确数字）
- Hero 自己是高牌时，「同牌型」一题同样跳过（不计入统计，题量退化为 2 步）
- `AAK83 > AAQ83`、`AAKKQ > AAQQK`、相同两对比较踢脚
- `A2345` 为 5 高顺子且 `23456 > A2345`
- 完全平手返回 0
- 1081 / 1035 / 990 组合无重复、无同一张牌重复、无 Blocker 泄漏
- 各类一致性：`ahead+tie+behind=当前街道组合数`、牌型 ahead 之和 = 总 ahead、点数类型之和 = 牌型 ahead、同牌型三项之和 = 同牌型总数
- 固定场景：翻牌圈 领先 28 / 平手 6 / 落后 1047；转牌 2s 后 71 / 6 / 958；河牌 9h 后 107 / 6 / 877；转牌成两对只剩 8 个组合能压过；河牌成葫芦只剩 44 个
- 概率区间边界 0 / 1% / 3% / 10% / 35% / 100% 无重叠（共 5 档：0～1%、1～3%、3～10%、10～35%、35～100%）
- Fixture：两对 21、A8=6、A3=6、83=9、三条 7
- 听牌：翻牌圈经典数字（378 / 340 / 178 / 45）不变；转牌圈 `next=final`、不可能出现后门听牌；河牌圈直接返回「已发完」
- `dealNextStreet`：翻牌 -> 转牌 -> 河牌 -> 幂等，新牌一定不在已知牌中，确定性随机源可复现
- Property Test：随机 1000 个翻牌圈场景 + 随机 60 个转牌 / 60 个河牌场景全部满足不变量（含「合并行内成员概率相同」）
- 评分：高牌被排除在漏选/多选/满分判定之外，即使它能压过 Hero

```bash

```

```text
poker-trainer/flop-trainer.html
```

- 开发专属的 `/debug` 调试页不会出现在分发包中

