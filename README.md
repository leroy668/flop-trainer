# 德州扑克相对牌力概率训练器

一个纯前端训练器：看到自己的 2 张底牌 + 公共牌后，快速判断

- 哪些牌型能压过我
- 各牌型的大致概率
- 同牌型中比我大的概率
- 具体是什么起手牌（A8 / A3 / 83 …）
- 各有多少组合

公共牌可以一路发到河牌，**翻牌圈 / 转牌圈 / 河牌圈都能出题与作答**：

| 街道 | 公共牌 | 对手组合数 |
| --- | --- | --- |
| 翻牌圈 | 3 张 | `C(47,2) = 1081` |
| 转牌圈 | 4 张 | `C(46,2) = 1035` |
| 河牌圈 | 5 张 | `C(45,2) = 990` |

> 本版默认对手从剩余未知牌中**完全随机**获得 2 张牌，每个组合等权。
> 所有概率都由当前街道的组合精确枚举得出，**没有任何硬编码**。

项目位于 `poker-trainer/` 子目录，与仓库里原有的菜谱应用完全独立。

## 2. 核心数据结构

```ts
type Rank = '2'|'3'|'4'|'5'|'6'|'7'|'8'|'9'|'T'|'J'|'Q'|'K'|'A';
type Suit = 's' | 'h' | 'd' | 'c';

interface Card { rank: Rank; suit: Suit; }

type Street = 'flop' | 'turn' | 'river';

interface Scenario {
  hero: [Card, Card];
  flop: [Card, Card, Card];
  turn?: Card;   // 发了转牌就是转牌圈
  river?: Card;  // 发了河牌就是河牌圈
}

enum HandCategory {
  HighCard = 0, OnePair = 1, TwoPair = 2, Trips = 3,
  Straight = 4, Flush = 5, FullHouse = 6, Quads = 7, StraightFlush = 8,
}

interface HandValue {
  category: HandCategory;
  tiebreak: number[]; // 从重要到次要
}
```

牌面工具（`src/poker/cards.ts`）：`boardCards(s)`、`knownCards(s)`、`streetOf(s)`、`remainingBoardCards(s)`、`getRemainingDeck(s)`（各街分别为 47 / 46 / 45 张）。

`HandValue` 示例：

| 牌面 | category | tiebreak |
| --- | --- | --- |
| `A♠ A♥ K♦ 8♣ 3♦` | `OnePair` | `[14, 13, 8, 3]`（A 对，K/8/3 踢脚） |
| `A♠ A♥ K♦ K♣ Q♦` | `TwoPair` | `[14, 13, 12]` |
| `A♥ 2♠ 3♦ 4♣ 5♥` | `Straight` | `[5]`（5 高顺，A 当 1） |

分析结果：

```ts
interface ScenarioAnalysis {
```

## 3. 核心算法

`analyzeScenario(scenario)` 完全按需求伪代码实现，对所有街道一致：

```text
52 张牌
  -> 移除全部已知牌（Hero 2 + 公共牌 3/4/5）= 47 / 46 / 45 张
  -> 枚举 C(n,2) = 1081 / 1035 / 990 个对手组合
  -> 对每个组合 evaluateBestHand([对手2张 + 公共牌])
  -> compareHandValues(对手, Hero)
  -> 聚合成 ahead / tie / behind（分母 = 当前街道的组合数）
  -> 按 9 个牌型聚合，再按类型聚合：常规牌型用底牌点数（A8 / 83），一对用成对点数并区分「配对公共牌 / 口袋对」，同花用高张
  -> 同一牌型内概率完全相同的类型再合并成一行，行名列出全部成员（如「配对公共牌 K / 9 / 6」「8 / 7高同花」）
  -> 同牌型单独聚合，使用条件概率分母 totalCount
```

关键点：

- **5~7 张取最优五张**：`evaluateBestHand(cards)` 枚举 `C(6,5)=6` / `C(7,5)=21` 个子集取最大，所以转牌 / 河牌圈“哪些牌能压过我”依然精确。
- **A2345 = 5 高顺子**（A 当 1），已覆盖普通顺子与同花顺。
- **同牌型也可能压过 Hero**：训练器判定“能否压过”依据 `category.aheadCount > 0`，而不是 `category > hero.category`。
- 两种概率严格区分：
  - 占全部随机手牌：`aheadCount / 当前街道组合数`
  - 同牌型条件下领先：`sameCategory.aheadCount / sameCategory.totalCount`
- 概率区间为 `[min, max)`，最后一个区间包含 100%，没有重叠。

### 街道推进（发转牌 / 发河牌）

`dealNextStreet(scenario, rng = Math.random)` 负责把牌面往前推一条街：

```text
翻牌圈 --发转牌--> 转牌圈 --发河牌--> 河牌圈 --再发--> 原样返回
```

- 新牌从 `getRemainingDeck(scenario)`（即全部未知牌）中**等概率抽一张**，不偷看任何人的底牌。
- 已发的公共牌不会被覆盖，河牌圈之后再调用会原样返回（幂等）。
- 每发一条街，`analyzeScenario` 的分母、`analyzeDraws` 的“下一张 / 发完为止”语义都会自动跟着变，**不需要任何特例分支**。

### Fixture 输出（手工核对）

`scripts/inspect.ts` 对 `A♠K♦ / A♥8♣3♦` 的实际输出：

```text

  两对: 21 组合 (1.94%)
    83: 9 组合 (0.83%)
    A8 / A3: 12 组合 (1.11%)
  三条: 7 组合 (0.65%)
    88 / 33: 6 组合 (0.56%)
    AA: 1 组合 (0.09%)

同牌型:
  一对 总数 369
  比你大 0 (0.00%) / 平手 6 / 比你小 363
```

同一手牌把转牌与河牌发出来（`--board="Ah 8c 3d 2s 9h"`），结果会自动换成河牌圈的分母：

```text
河牌圈（还要发 0 张公共牌）
Hero: 一对A，K98踢脚
总体: 领先 107 / 平手 6 / 落后 877 = 990
```

- 两对合计 `21 = A8(6) + A3(6) + 83(9)`，与需求第 54~57 条完全一致（A8 / A3 概率相同，展示时合并为一行）。
- Blocker 由算法动态计算：剩余 A=2、8=3、3=3，故 A8=2×3=6、A3=2×3=6、83=3×3=9。

### 后续听牌分析（`src/poker/draws.ts`）

回答“我这手听牌到底能补成多少”与“对手拿到听牌并补成的概率有多大”。同样是**精确枚举**，不用蒙特卡洛。

```text
已知 5~7 张牌（Hero 2 + 已发公共牌）
  -> 先判断“现在还没有成型”的听牌目标（顺子 / 同花）
  -> 下一张牌：池子里每张牌逐个试，数出真正能补成的张数 = outs
  -> 发完为止：枚举 C(n,2) 个后续组合，数出能补成的组合数
  -> 还要发两张、但下一张 0 张补牌而两张能补成 => 后门听牌
```

| 街道 | 下一张（next） | 发完为止（final） | 后门听牌 |
| --- | --- | --- | --- |
| 翻牌圈（还要发 2 张） | 转牌 `47` 张（Hero）/ `45` 张（对手） | 转牌 + 河牌 `C(47,2)=1081` / `C(45,2)=990` | 成立 |
| 转牌圈（还要发 1 张） | 河牌 `46` 张 / `44` 张 | **与「下一张」同一批牌**（`46` / `44`） | 不成立（只剩一张牌，不可能“连来两张”） |
| 河牌圈（不用再发） | — | — | 面板不显示：已经没有后续牌可发 |

代码里的字段叫 `next*` / `final*`（而不是 `turn*` / `river*`），就是为了同一套逻辑能直接跑在任意街道上：`remainingBoardCards === 1` 时 `next` 与 `final` 数值相同，界面上也只显示一列。

关键点：

- **判断“补成”用的是花色张数 / 点数位掩码，不是牌型比较**：葫芦、四条并不包含同花，所以不能用“牌型 ≥ 同花”来判断；顺子同理（预计算 8192 项 `STRAIGHT_MASK_TABLE`，含 A2345 轮子）。
- **只把“现在还没成型”的目标当听牌**：同花听牌要求当前同花色恰好 4 张，顺子听牌要求再加 1 张就能连成 5 张。已成型的牌型不会被当成听牌（注意：这是用**全部已知牌**判定的，所以转牌 / 河牌发到同花后就不会再算同花听牌）。
- **顺子听牌按补牌点数分类**：1 个点数 = 卡顺（4 张）、2 个点数 = 两头顺（8 张）、≥3 个点数 = 多卡口。
- **对手侧每类听牌的组合数是重叠的**（同一个组合可能既是同花听牌又是顺子听牌），所以额外给出一条不重叠的三分法：`有立即听牌 + 只有后门听牌 + 完全没有听牌 = 当前街道组合数`。

经典数字（全部由枚举得出，测试里逐一锁定）：

| 听牌 | 补牌 | 下一张补成 | 到河牌补成 |
| --- | --- | --- | --- |
| 同花听牌（4 张同花） | 9 | `9/47 = 19.15%` | `378/1081 = 34.97%` |
| 两头顺（8 张补牌） | 8 | `8/47 = 17.02%` | `340/1081 = 31.45%` |
| 卡顺（4 张补牌） | 4 | `4/47 = 8.51%` | `178/1081 = 16.47%` |
| 后门同花（3 张同花） | 0 | `0%` | `C(10,2)=45/1081 = 4.16%` |
| 同花听牌（转牌圈，只剩一张） | 9 | `9/46 = 19.57%`（= 最终补成） | —— |

## 4. 训练页面流程

1. **显示牌面**：Hero 两张 + 翻牌（还没发的公共牌显示为虚线空位），并显示 Hero 当前牌型与当前街道（不泄露概率）。
2. **选择压制牌型**：8 个成牌型多选（一对及以上，不含「高牌」）；同牌型更大的组合也算正确。
3. **确认牌型**后，对每个已选牌型选择「该牌型且压过你」的概率区间（分母 = 当前街道组合数）。
4. **同牌型判断**：在“对手与 Hero 同牌型”的条件下，选择「比你大」的概率区间（分母为同牌型总数）。仅当 Hero 是成牌时才出现；Hero 是高牌时本题跳过（题量变为 2 步，直接提交）。
5. **提交并揭晓**：结果页分成选项卡查看（见下）。
6. **发下一条街**：结果页底部有「**发转牌**」/「**发河牌**」按钮，发牌后公共牌变化，**当成新的一题重新作答**；河牌发完后按钮变成「下一题」，换一手全新牌。
7. **退回去**：发过牌之后，牌面下方（作答时）与底部操作条（结果页）会出现「**↩ 回到翻牌圈** / **↩ 回到转牌圈**」按钮，可以一街一街地往后退，**退回去时会连上一街的作答与结果一起恢复**。
8. 顶部统计：牌型判断正确率、概率区间正确率、同牌型判断正确率、连续正确次数。

> 每一街都是独立的一题（相同的三步流程），所以转牌 / 河牌圈也能练“对手现在能压过我多少”。
> 统计口径不区分街道，所有街道的正确率合在一起。
> 收回（undo）只恢复牌面与当街的作答状态，**不会**把已经计过的统计回退。

### 结果页选项卡

结果页不再把几块内容纵向堆在一起，而是选项卡，一次只看一块：

| 选项卡 | 内容 | 卡片上的摘要 / 标记 |
| --- | --- | --- |
| 总体牌力 | 领先 / 平手 / 落后占比条 + 领先牌型构成 | 对手领先概率 |
| 能压过你的牌型 | 每种能压过你的牌型（含逐个点数类型、具体花色）+ 你的估计与对错 | `n 种 · 组合数 / 当前街道组合数`，以及牌型判断 ✓ / ✗ |
| 同牌型内部（`牌型`） | 同牌型中比你大 / 平 / 小的条件概率 + 具体手牌 | `同牌型总数 · 比你大 x%`，以及同牌型判断 ✓ / ✗ |
| 5 张牌分析 | ① 当前 5 张牌归类成一句类型；② 发完后最终牌型的分布；③ 后续听牌（转牌 / 河牌）；④ 对手的听牌 | `当前类型 · 听牌 n 种 / 无听牌` |

- **四个选项卡在翻牌 / 转牌 / 河牌三街都保留**，同一套位置上从「翻牌圈能补成什么」一路看到「发完了、牌型定型」。

实现要点：

- **本题小结**：作答后选项卡上方先给一行「牌型判断 / 概率区间 x / y 对 / 同牌型判断」的对错，一眼就能看出哪里错了，不用逐个选项卡找。
- **懒渲染**：只渲染当前选项卡的那一块。发完后最终牌型的枚举（翻牌圈 1081 个后续）只在你切到「5 张牌分析」时才跑，答题时不计算。
- 选项卡上的 ✓ / ✗ 对应「这一步答对没有」：能压过你的牌型 → 牌型多选是否正确；同牌型内部 → 同牌型区间是否正确（Hero 是高牌时不要求作答，因此不打标记）。概率区间的对错在面板内逐条标出。
- 直接看答案模式下没有作答，因此不打 ✓ / ✗。
- 窄屏（≤ 520px）自动改用短标题并隐藏摘要行，选项卡仍在一行内（高约 50px）。
- 选项卡样式为 `position: sticky`（吸顶），方便在不滚回顶部的情况下切换。
- 语义上用「一组开关」（`role="group"` + `aria-pressed`）而不是 `tablist`，因为面板是切一个才挂载一个的，这样不依赖方向键导航也不会让屏幕阅读器以为存在隐藏面板。

### 收回上一街（退回发牌之前）

发牌本身是**可逆**的：每次发牌前先把当前状态压一份快照（`{ scenario, phase, answer, score }`），收回时弹出快照并整份恢复，所以退回去看到的还是“发牌之前”的那一页（包括已经揭晓的结果与 ✓ / ✗），而不是重开一题。

| 位置 | 按钮 |
| --- | --- |
| 作答页（牌面下方） | `↩ 回到翻牌圈` + 「收回转牌，回到翻牌继续」 |
| 结果页 / 直接看答案（底部操作条） | `发河牌 ▶` · `下一题` · `↩ 回到转牌圈` |

- 快照是一个**栈**：翻牌 -> 转牌 -> 河牌可以连退两次，一直退到翻牌圈。
- 「换一题」/「下一题」会清空快照栈（新的一手牌没有“发牌之前”可退）。
- 退回后高亮（`board__group--new`）会清除，不会留着让人误以为那张牌刚发。
- 退回去之后可以重新发牌，**新发的牌重新随机**（不是同一个转牌 / 河牌）。

### 「5 张牌分析」面板（`src/poker/handType.ts` + `src/poker/outlook.ts`）

回答“我现在这 5 张牌到底算什么、往后的概率怎么样”。分四块：

1. **归类**：把当前 5 张牌压成一句人话——`顶对 + 同花听牌 ♠`、`空气（没有成牌，也没有听牌）`、`高牌 + 后门顺子听牌`。左侧色条按类型换色（已成牌蓝 / 强牌绿 / 听牌紫 / 空气灰），两种听牌同时存在时打「双听牌」标签。细分规则：
   - 一对：`超对`（口袋对大于公共牌最大牌）/ `顶对` / `中对` / `底对` / `小对子`（口袋对小于公共牌）/ `公共牌对`（公共牌成对、底牌都只是踢脚），并把配中的那张牌写进括号，如「配中公共牌最大牌 A」。
   - 三条：`暗三条`（口袋对配中公共牌）/ `明三条`（底牌配中公共牌的对子）/ `公共牌三条`（公共牌自己就是三条，底牌只提供踢脚）。
   - 高牌：`A 高，两张高张 / 一张高张 / 两张都是小牌`。
   - 两对及以上直接用评价器的描述（`两对A8，3踢脚`、`葫芦，A带K`）。
2. **已成牌明细**：括号里给出判断依据。
3. **发完后最终牌型的分布**（`analyzeHeroOutlook`）：把剩余公共牌的所有取法**枚举**一遍（翻牌圈 `C(47,2)=1081`、转牌圈 46、河牌圈 1），每个后续都按「7 张取最优五张」评价，再按牌型类别分组。每行标「提升 / 保持」（只可能变强，不会变弱），底部给标题数字「最终强于现在的概率」，以及「最高能补成」哪一种。**没有任何写死的概率**，全部来自枚举。
4. 后面接原有的**后续听牌**面板（见下）。

```text
Hero As Kd / 翻牌 Ah 8c 3d
  归类：顶对（配中公共牌最大牌 A）
  1081 个等权后续：四条 1 / 葫芦 27 / 三条 72 / 两对 405 / 一对 576
  最终强于现在的概率 505 / 1081 = 46.72%
```

- 归类与分布只在**结果阶段**渲染，题目页不会出现（避免提前泄露答案）。
- 归类标签由 `ResultBreakdown` 算一次（很便宜），分布则由 `HandOutlookPanel` 在自己挂载时才算（翻牌圈约 60~90 ms），所以只有切到这个选项卡才付这个代价。
- 河牌圈没有后续牌，分布区换成一句「公共牌已经发完，牌型已经定型」；归类仍然照常给。
- **听牌只在还有后续公共牌时才算**：`analyzeBase` 在 `remainingBoard === 0` 时直接返回空听牌（`analyzeHeroDraws` 同样），所以河牌圈不会出现“下一张能补成同花”这种荒谬结果。

### 后续听牌面板

结果页「5 张牌分析」选项卡的后半部分，分两块：

- **你的听牌**：每个听牌一行，列出补牌点数与具体补牌（如 `2♠ 6♠ …`），以及「转牌 `n/47`」「到河牌 `n/1081`」两种成牌概率；后门听牌会打上「后门 · 转牌补不成，需连来两张」标签；多于一种听牌时再给一行「至少补成一种听牌」的并集。**转牌圈只剩一张河牌，所以只显示「河牌 `n/46`」一列**。
- **对手的听牌**：先给不重叠的三分法（有立即听牌 / 只有后门听牌 / 完全没有听牌），再按听牌类型列组合数与占比，以及「下一张补成（平均）」「到河牌补成（平均）」「拿到且补成」三个指标；最后一行为标题数字——「随机对手拿到听牌并在河牌前补成」的概率（括号内是只看“有听牌”时的条件概率）。转牌圈会把「到河牌补成」这一列并掉，表格只剩 4 列。

颜色约定：**红色 = 该类听牌占全部随机组合；蓝色 = 拿到该类听牌后的平均补成率；紫色 = 对手拿到该类听牌且真的补成**。

这一面板只在结果页渲染，而且只有切到该选项卡才计算（由 `ResultBreakdown` 挂载），因此**答题时完全不会触发枚举，不会拖慢答题**。同花听牌行会带花色（如「同花听牌 ♠」）。河牌圈没有后续牌，`analyzeDraws` 与 `analyzeHeroDraws` 都会直接返回空结果，面板只显示一句「河牌已经发完……」。

### 翻牌牌型图鉴（`#/flop-types`）

训练页右上角的「**翻牌牌型图鉴**」链接（哈希路由 `#/flop-types`，与训练流程完全独立）会打开一个单独的页面：把「Hero 2 张 + 翻牌 3 张」的**全部 25,989,600 种等权组合**归类成相似牌型，并按出现频率排序。适合先建立“翻牌大概会变成什么”的整体印象，再回去做题。

**枚举口径（全部现场算出来，没有任何预置表格）**

1. 总空间 = `C(52,2) × C(50,3) = 1326 × 19600 = 25,989,600`。
2. 整体置换花色不改变已成牌、听牌、配对位置，所以先按花色同构把 5 张牌组合压缩成**等价类（轨道）**：2,598,960 → **134,459** 个轨道，每个轨道带权重 `24 / |稳定子|`。权重之和恰好是 2,598,960。

4. 花色相关的听牌结构（同花听牌 / 后门同花 / 顺子补牌点数）只与这 5 张牌有关，**每个轨道只算一次**，10 种切分共用；只有一对的位置（超对 / 顶对 / …）与切分有关。

### 牌面结构图鉴（`#/board-textures`）

训练页右上角的「**牌面结构图鉴**」链接（哈希路由 `#/board-textures`）是另一条轴：它**只看翻牌自己**——三张牌的点数关系、有没有成对、同花结构，与 Hero 的底牌完全无关。因此它的分母是**全部 `C(52,3) = 22,100` 种翻牌**（不是牌型图鉴的 25,989,600，也不是已知底牌后的 `C(50,3) = 19,600`）。

**三档粒度（同一遍枚举，三种压缩方式）**

| 粒度 | 类数 | 合并规则 | 每类平均 |
| --- | ---: | --- | ---: |
| 策略牌面 | **1,755** | 点数保留，整体置换 4 种花色后相同即同类（GTO 软件建翻牌库的「策略上不同的翻牌」口径） | 12.6 种 |
| 牌面形状 | **379** | 再把点数整体平移也合并（`A♦K♥Q♠` 与 `K♦Q♥J♠` 同形状），只留跨度 / 间隔 / 哪几张同花 | 58.3 种 |
| 形状 × 花色 | **247** | 在形状基础上只分单色 / 两色 / 彩虹，不再区分两色时是哪两张同花 | 89.5 种 |

三档都是把 22,100 种翻牌**逐个枚举现场算出来**的（约 0.1 s，页面同步算完，不需要进度条），没有任何预置表格：

1. 枚举 `C(52,3)` 的全部 22,100 个三张牌组合（i<j<k 遍历牌堆）。
2. 给每个组合算三个整数 key：花色置换等价码（策略）、再加上点数平移等价码（形状）、点数形状 × 花色数（粗粒度）。键是纯数字打包，所以整趟只花约 0.114 s。
3. 同一 key 归一类，累加该类包含的具体翻牌数；占比 = 该类翻牌数 ÷ 22,100。

**校验过的数字**：类数 1,755 / 379 / 247；每类权重的花色轨道大小只可能是 4 / 12 / 24（分别是 299 / 1,170 / 286 类，`Σ 权重 = 22,100`）；三档各自的占比之和都等于 100%；三档的类标签互不重复（测试里逐一断言）。原始花色结构：两色 55.06%（12,168）、彩虹 39.76%（8,788）、单色 5.18%（1,144）；成对结构：无对 82.82%（18,304）、带对 16.94%（3,744）、三条 0.235%（52，只可能是三张不同花）。

页面结构：

- 顶部一条三色占比条 + 可点选的分组卡片（花色：两色 / 彩虹 / 单色；成对：无对 / 带对 / 三条），点一下就是筛选条件，可以和下面的搜索框叠加。

- 三档切换 + 文字筛选（`AKQ` / `两色` / `三连张` / `带对` / `A` 高…），每类一行：类名、占比（大字号）、条形对比、这一类有多少种翻牌、一个具体例子。

### 模拟牌桌（`#/table`）

训练页右上角的「**模拟牌桌**」链接（哈希路由 `#/table`）是一个独立的练习场：你 + **1 ～ 5 个电脑玩家**（2 ～ 6 人桌，人数随时加减），用的是**简化的固定额度下注流程**（盲注、轮换庄家、逐街下注、边池、摊牌）。

> **本桌不是标准无限注德州扑克。** 只有两条关键改动：
> 1. **下注 / 加注只有 5 / 10 / 20 三档，而且 20 封顶**——档位指的是「你这一条街在自己面前**一共投入多少**」，不是「再加多少」。所以一条街最多就是 5 → 10 → 20 三次加注（翻牌前大盲已经是 10，最多只能加到 20），按钮上只会有「下注 10」「加注到 20」，**永远不会出现「加注 20（到 30）」**。
> 2. **翻牌前禁止全下、翻牌后才能全下**——全下不受 20 封顶限制（一次推进全部剩余筹码，也算一次加注）。
>
> 其余（盲注、买入、边池）只是为了让牌局跑起来的配套规则。

**本桌规则（刻意简化，只保留训练需要的部分）**

| 项目 | 规则 |
| --- | --- |
| 人数 | 默认 4 人（你 + 机器人 A/B/C），工具栏的「对手数量」可以调成 **1 ～ 5 个机器人**（2 ～ 6 人桌）；改人数会立刻开一桌新的，可用 ↩ 撤回上一步退回原来那桌 |
| 单挑 | 只有你和一个机器人时按标准单挑规则：**庄家下小盲**、翻牌前先说话，翻牌后换大盲先说话 |
| 买入 | 每人 200 筹码；筹码低于 20 时下一手开始前自动补码，手与手之间也能手动「补码到 200」 |
| 盲注 | 小盲 5 / 大盲 10，每手轮换庄家（翻牌前大盲左手边先说话，翻牌后庄家左手边先说话） |
| 下注 | 只有 **5 / 10 / 20** 三档，**20 封顶**；档位 = 本街你在自己面前的总投入，所以按钮是「下注 10」「加注到 20」（跟注则按对手的下注额补齐，可以是任何数）。20 封顶之后没人能再加注，一条街最多 5 → 10 → 20 三次 |
| 全下 | **翻牌前不能全下**（加注后必须留至少 1 个筹码；筹码不够跟注时只能弃牌）；**翻牌后可以全下**，且不受 20 封顶限制 |
| 摊牌 | 7 张取最优 5 张；投入不等的全下按主池 / 边池分配，平手平分，零头给庄家左手边第一位 |

**引擎是纯函数**（`src/poker/table.ts`）：`createTable -> startHand -> legalActions -> applyAction -> 结算`，随机数发生器只是一个整数 seed（`src/poker/rng.ts` 的 mulberry32，seed 存在 `TableState.rngSeed` 里）。因此**同一份状态 + 同一个动作必然得到同一个结果**，测试可以逐手复现；底池恒等于「所有人已投入之和」（`pot = Σ committedTotal`），所以每打完一手都能断言「筹码总量不变」。

**电脑玩家**（`src/poker/ai.ts`）：

- 翻牌前：用校准过的**起手牌强度**公式（对子 / 高张 / 同花 / 连张），按需跟注额调整门槛。
- 翻牌后：**精确枚举**当前公共牌下对手所有两张组合，得到「成牌强度」；听牌补成概率直接复用训练器的补牌统计；综合胜率 `= made + (1-made) × draw × 0.85`，再按对手数取幂（多路用独立近似，中强牌会略低估），最后跟底池赔率比较。
- 四个座位有固定的性格（保守 / 激进 / 平衡 / 松凶，各自的跟注容忍度、加注阈值、偷鸡概率不同），并且**每个动作都先过 `legalActions`**，所以不可能出现非法动作。

**页面交互**

- 牌桌：公共牌 5 个位置、底池、街道、还在局里的人数，以及「轮到你时需跟注 N（底池赔率 x%）」。
- 4 个座位：名字、庄 / 小盲 / 大盲标记、筹码、已下注额、本街动作；电脑底牌默认扣着（摊牌时只亮参与摊牌的人），可以打开「亮出电脑底牌」全程透明对照。
- 行动区：按钮直接由 `legalActions` 生成（弃牌 / 过牌 / 跟注 N / 下注 5·10·20 / 加注到 10·20 / 全下 N），翻牌前的加注按钮永远不会出现「全下」；由于 20 封顶，本街注已经是 20 时加注按钮会消失，只剩跟注 / 弃牌（翻牌后还有全下）。
- 「你的牌力估计」面板（可关）：起手牌强度或成牌强度 + 听牌补成概率 + 综合胜率，并说明每个数字是枚举出来的还是估计的。
- 电脑思考速度（慢 / 正常 / 快）、**↩ 撤回上一步**（连电脑的动作一起回退，退回后电脑可能改主意，因为随机数发生器在页面里持续推进）、每手结束后的结算账单（每个池的金额与得主、每个座位的盈亏）+「下一手 ▶」。
- 三个开关（思考速度 / 显示胜率估计 / 亮出电脑底牌）与**对手数量**都会记进 `localStorage`（`flop-trainer:table-*`），下次打开还是同一套设置；行动区下面还会按当前街道提示「翻牌前不能全下」或「翻牌后可以全下」。
- 「牌桌记录」按街道列出每一手发生了什么，最新的在最上面。

```text
#/table
  第 1 手 · 翻牌前 · 底池 15 · 还在局里 4 人
  你 200 / 机器人 A 195 / 机器人 B 190 / 机器人 C 200
  轮到你行动：弃牌 / 跟注 10 / 加注到 20
  你的牌力估计：起手牌强度 57.9% · 综合胜率（对 3 个对手）约 19.4%
```

> 与前 6 节不同，这一页**故意包含下注 / 底池赔率**——它是个独立的小游戏，不影响训练器的题目与统计；训练器本身依然不涉及任何下注策略。

### 直接看答案开关

右上角有「**直接看答案**」开关（选择会记入 localStorage）：
